# Repository-derived migration inventory

## Evidence boundary

This inventory is derived only from tracked repository files at starting
`main` SHA `a21cd2dd90286633c08b99d83eb8a15cdf68c869`. It is not an inventory of the
live Lovable Cloud project and does not prove which migrations ran, which
runtime configuration drifted, or what a future export contains. Secret values,
owner email values, hardcoded user UUID values, and credential-like literals
are intentionally omitted.

The detailed evidence is split into reproducible appendices:

- [`sql-inventory.md`](sql-inventory.md) inventories every SQL-defined object,
  constraint, policy, grant, publication, cron/storage statement, drop, and
  code/schema gap.
- [`sql-migrations.sha256`](sql-migrations.sha256) is the machine-checkable,
  chronological SHA-256 ledger for all 281 migration files.
- [`runtime-inventory.md`](runtime-inventory.md) inventories all 120 Edge
  Function directories, shared imports, configuration-name dependencies,
  integrations, Auth, Storage, Realtime, cron, and hardcoded bindings.
- [`edge-functions.json`](edge-functions.json) is the reproducible strict
  manifest of function slugs, source-directory digests, and whether
  `verify_jwt` is explicit.

## Reconstruction gaps requiring explicit disposition

Generated database types declare these tables without a chronological
`CREATE TABLE` migration: `account_dossiers`, `account_risks`, `agent_configs`,
`agent_events`, `agent_trust`, `branch_pov`, `calendar_events`,
`competitive_intel`, `curriculum_concepts`, `curriculum_gates`,
`dismissed_duplicates`, `ki_annotations`, `ki_curriculum`,
`strategy_benchmark_runs`, `user_band_gate`, `user_competency`,
`vertical_briefs`, and `verticals`. They also declare view
`ki_curriculum_full` and functions `monitor_counts` and
`morning_line_signals`. Literal code expects `canonical_resource_status` and
RPC `increment_template_selection`, neither present in migrations or generated
types. These are fail-closed rehearsal questions, not candidates for guessed
replacement SQL.

## Inventory conclusion

The repository provides a strong code/schema intent ledger, but not a complete
production inventory. In particular, the migration sequence cannot reconstruct
all types/code expectations by itself, 78 Edge Functions lack an explicit JWT
setting, most jobs are absent from chronological migrations, Auth/Storage and
configuration are incomplete, and a Realtime subscription target lacks a
publication migration. The migration remains blocked on a real export rehearsal
and runtime inventories even if every local tool test passes.
