# Repository-derived migration inventory

## Evidence boundary

This original inventory is derived only from tracked repository files inspected
on 2026-07-14 at starting `main` SHA
`a21cd2dd90286633c08b99d83eb8a15cdf68c869`. It is not an inventory of the live
Lovable Cloud project and does not prove which migrations ran, which runtime
configuration drifted, or what a future export contains. Secret values, owner
email values, hardcoded user UUID values, and credential-like literals are
intentionally omitted.

Credential-containment statements added on 2026-07-15 are a separate addendum
bound to draft PR #17 substantive commit
`00680fdf0d766912bfc4be86ffa8791925e8f7d3`. They describe the sanitized
repository snapshot at that commit and do not move the original inventory's
observation point or establish any runtime fact.

The detailed evidence is split into reproducible appendices:

- [`sql-inventory.md`](sql-inventory.md) inventories every SQL-defined object,
  constraint, policy, grant, publication, cron/storage statement, drop, and
  code/schema gap.
- [`sql-migrations.sha256`](sql-migrations.sha256) is the machine-checkable,
  chronological SHA-256 ledger for all 281 migration files.
- [`runtime-inventory.md`](runtime-inventory.md) inventories all reviewed Edge
  Function directories, shared imports, configuration-name dependencies,
  integrations, Auth, Storage, Realtime, cron, and hardcoded bindings.
- [`edge-functions.json`](edge-functions.json) is the reproducible strict
  manifest of function slugs, resolved deployment-closure fingerprints, and
  structured effective `verify_jwt`/entrypoint/import-map settings.

## Inventory conclusion

The repository provides a strong code/schema intent ledger, but not a complete
production inventory. In particular, the migration sequence cannot reconstruct
all types/code expectations by itself, 78 Edge Functions rely locally on the
documented omitted JWT default without deployed-runtime proof, most jobs are
absent from chronological migrations, Auth/Storage and configuration are
incomplete, and a Realtime subscription target lacks a publication migration.
The migration remains blocked on a real export rehearsal and runtime inventories
even if every local tool test passes.
